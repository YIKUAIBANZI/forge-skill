# 替身 (Stand-in) - Product Requirements Document

## 一、产品定位

**产品名**：替身 (Stand-in)  
**类型**：Claude Code Skill  
**核心价值主张**：当用户看不清自己时，用数字替身帮用户重新看清自己

### 问题陈述

人在自己的处境里，很难理智看清自己。很多私人决策之所以难，不是因为缺少道理，而是因为：

1. 人身处局中，视野有限
2. 情绪干扰判断（焦虑/兴奋/恐惧都会扭曲评估）
3. 当前环境绑架思路（周围人的观点渗透进自己的"独立判断"）
4. 很多建议虽然正确，但脱离实际处境

### 解决方案

不是找"最正确的人"给建议，而是**调出多个不同版本的自己**，让它们代替用户从局外审视当前处境。

---

## 二、核心概念

### 人格底座 (Personality Foundation)

通过对话采集和素材分析，提取用户的五层人格结构：

| 层级 | 名称 | 优先级 | 主要内容 |
|------|------|--------|----------|
| L0 | 硬性覆写 | 最高 | 用户的绝对底线和原则 |
| L1 | 身份认同 | 高 | 基本信息、职业、人生阶段、MBTI |
| L2 | 表达风格 | 中 | 说话方式、用词习惯、沟通模式 |
| L3 | 决策模式 | 核心 | 8个维度参数（风险/时间/情感等）、决策过程 |
| L4 | 价值观与盲区 | 核心 | 核心价值排序、已知盲区、情绪触发点、自我矛盾 |

### 替身变体 (Stand-in Variants)

基于人格底座，根据具体决策场景的矛盾轴自动生成 3-4 个变体：

- 每个变体基于同一底座，只是某些 L3 参数被偏移
- 变体根据场景定制（不是固定模板）
- 变体用用户自己的语言风格说话

### 渐进式讨论 (Progressive Discussion)

三阶段输出：
1. **独立分析**：每个变体各自表态
2. **交叉质疑**：变体互相挑战盲区
3. **综合呈现**：共识、分歧、代价清单

## 三、用户流程

### 主流程一：创建替身

```
用户输入"创建替身"
    → 检查是否已有替身（有则询问更新/重建）
    → 第一轮对话：基础画像（5-8问）
    → 第二轮对话：决策风格（6-8个情景题）
    → 第三轮对话：价值观探测（排序+开放题）
    → 第四轮：素材导入（可选，支持微信/日记/社交媒体）
    → 人格分析生成 persona.md
    → 向用户展示摘要，确认"哪里不像"
    → 迭代纠正直到用户认可
    → 存档
```

### 主流程二：使用替身决策

```
用户输入"替身会议"
    → 加载 persona.md
    → 采集决策场景（选项/利害/情绪/已有倾向）
    → 分析矛盾轴
    → 生成 3-4 个变体，展示阵容
    → Phase 1：独立分析
    → 用户确认/追问后进入 Phase 2
    → Phase 2：交叉质疑
    → 用户确认后进入 Phase 3
    → Phase 3：综合呈现
    → 收尾，邀请用户反馈结果
```

## 四、技术规格

### 素材解析支持

| 来源 | 格式 | 解析器 |
|------|------|--------|
| 微信聊天记录 | txt, html | wechat_parser.py |
| 社交媒体 | json, txt | social_parser.py |
| 日记/笔记 | md, txt, json | diary_parser.py |
| 跨源综合 | — | journal_analyzer.py |

### 决策参数维度（L3）

| 参数 | 刻度 | 含义 |
|------|------|------|
| risk_appetite | 1-10 | 1=极度保守 / 10=极度冒险 |
| time_horizon | 1-10 | 1=只看眼前 / 10=只看长期 |
| emotion_weight | 1-10 | 1=纯理性 / 10=纯感性 |
| social_reference | 1-10 | 1=完全不在乎外界 / 10=高度在意外界看法 |
| action_bias | 1-10 | 1=反复思考不行动 / 10=想到就做 |
| control_need | 1-10 | 1=随遇而安 / 10=必须掌控一切 |
| novelty_seeking | 1-10 | 1=安于熟悉 / 10=渴望新鲜 |
| conflict_style | 1-10 | 1=极度回避 / 10=正面对抗 |

### 变体生成规则

1. 分析场景矛盾轴（最多识别 3 个）
2. 沿矛盾轴偏移底座参数生成变体（偏移量：±2 到 ±4）
3. 同时保留一个"自然的你"（不偏移）
4. 总变体数：3-4 个

## 五、设计原则

### 不评判
替身不是心理咨询师，不做价值判断。用户说"我就是容易冲动"，记录"冲动"，不纠正。

### 不美化
替身要像用户本人，包括缺点和盲区。一个完美的替身毫无用处。

### 不给"正确答案"
替身的输出是"代价清单"和"共识/分歧"，不是"你应该选A"。

### 用户拥有最终解释权
即使行为数据和用户自述矛盾，最终以用户确认为准。

### 隐私优先
所有数据本地处理，不上传，不存储原始聊天内容。

## 六、差异化

### 对比 ex-skill / colleague-skill

| 维度 | ex/colleague-skill | 替身 (Stand-in) |
|------|-------------------|-----------------|
| 蒸馏对象 | 他人 | 用户自己 |
| 输出数量 | 单一人格 | 多变体 |
| 应用场景 | 陪伴/工作 | 决策辅助 |
| 变体策略 | 无 | 情境自动生成 |
| 特有层级 | — | L4 价值观与盲区 |
| 讨论机制 | 无 | 三阶段渐进式 |

### 核心创新点

1. **蒸馏自己而非他人**：解决"了解自己"而非"模拟他人"
2. **情境自动变体**：不预设固定变体，根据场景矛盾轴动态生成
3. **L4 价值观与盲区层**：专为决策辅助设计，是其他人格蒸馏项目没有的层级
4. **渐进式讨论引擎**：从分析到质疑到综合，完整的内心辩论流程
5. **不给答案**：终态是"代价清单"而非"最优解"，尊重用户的自主性

## 七、未来方向

- **决策日志**：记录用户实际选择和结果，反哺替身的决策参数准确度
- **场景模板库**：常见决策场景（跳槽/分手/投资）的快速启动模板
- **多替身对话**：支持不同时期的自己进行横向对比（"三年前的你会怎么看？"）
- **情绪感知**：在对话中检测用户情绪状态，动态调整分析策略
