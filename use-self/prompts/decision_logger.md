# 决策日志 (Decision Logger)

在每次替身会议结束后，记录本次决策过程。随着记录积累，系统会逐渐了解你的真实决策模式，并反馈到人格参数的准确度上。

## 会议结束后：记录本次决策

```
替身会议结束了。

要把这次分析存入你的决策日志吗？
以后可以回来填写实际选择和结果，
日志积累多了会帮你发现自己的决策规律。

（输入"记录"保存，或直接跳过）
```

### 记录内容

```json
{
  "id": "[时间戳]",
  "created_at": "[今天日期]",
  "title": "[用一句话概括这个决策]",
  "scenario": "[用户描述的场景摘要]",
  "options": ["选项A", "选项B"],
  "variants_generated": ["稳健的你", "果断的你", ...],
  "variant_positions": {
    "稳健的你": "选项A",
    "果断的你": "选项B"
  },
  "key_tensions": ["安全 vs 成长", ...],
  "consensus": ["所有替身都同意的点..."],
  "core_disagreements": ["核心分歧..."],
  "user_initial_lean": "[用户开始时的倾向]",
  "user_final_choice": "",     ← 事后填
  "outcome_notes": "",         ← 事后填
  "regret_level": -1           ← 事后填（1-10）
}
```

调用 `tools/decision_logger.py` 的 `log_decision()` 保存。

## 事后回填结果

当用户说"更新决策结果"、"我决定了"、"告诉你结果"时：

```
你之前还有几个待填写结果的决策：

1. [标题] —— [日期]
2. [标题] —— [日期]

哪个有结果了？
```

收集：
- 最终选择了什么
- 现在回看觉得怎么样
- 后悔程度（1=完全不后悔，10=非常后悔）

调用 `tools/decision_logger.py` 的 `update_outcome()` 更新。

## 参数反馈分析

当用户说"分析我的决策规律"、"替身准不准"时：

调用 `tools/decision_logger.py` 的 `generate_params_feedback()`，输出：

```
基于你过去 [N] 条有结果的决策，我发现：

【变体预测准确率】
你的实际选择和替身预测的一致率是 XX%。
[高：参数准确 / 中：部分偏差 / 低：建议重新校准]

【后悔模式】
后悔程度较高的决策集中在：[描述]
后悔程度低的决策通常是：[描述]

【建议】
[是否需要更新 L3 参数]
```

如果分析发现明显的参数偏差，引导用户运行 `/forge-self` 更新人格底座。
