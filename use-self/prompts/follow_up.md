# 决策追踪与回访 (Follow-up)

> 处理三件事：
> 1. 替身会议结束时，记录本次决策到 decisions.json
> 2. 用户回来告知结果时，回填 follow_up
> 3. 用户想回顾决策规律时，分析 decisions.json

---

## 模式 1：记录新决策

**触发时机**：替身会议 Step 4 结束，用户说了倾向方向之后。

### 写入 decisions.json

文件路径：`personas/self/{name}/decisions.json`

如文件不存在，创建并写入空数组 `[]`，然后追加：

```json
{
  "id": "自动生成的 8 位随机 ID，如 'a3f2b1c9'",
  "date": "ISO date",
  "scenario": "一句话概括决策场景",
  "options": ["选项A描述", "选项B描述"],
  "variants_summary": {
    "稳健的你": "一句话概括其立场",
    "果断的你": "一句话概括其立场",
    "长线的你": "一句话概括其立场"
  },
  "user_lean": "用户会议后的倾向方向（用户的原话或简短概括）",
  "confidence_at_decision": "high | medium | low（基于用户说倾向时的措辞判断）",
  "follow_up": null
}
```

写入后告知用户：
```
记下来了。

三个月后我会提醒你回来填结果——
决策日志多了会帮你看清自己的规律。
```

## 模式 2：回填结果

**触发时机**：用户说"我选了X"、"告诉你结果"、"更新决策结果"。

### 流程

1. 读取 `decisions.json`，找出 `follow_up: null` 的条目
2. 如果有多条未完成，展示列表让用户选择哪一条
3. 问用户：
   ```
   说说你最终怎么选的，结果怎么样？
   
   - 你选了哪个方向？
   - 现在回看，满意吗？（1-10 分）
   - 从这个决定里，你学到了什么？
   ```
4. 将回答写入对应条目的 `follow_up`：
   ```json
   "follow_up": {
     "date": "ISO date",
     "final_choice": "用户最终选择",
     "outcome": "结果描述",
     "satisfaction": 7,
     "lesson": "用户自己的总结"
   }
   ```

5. **参数反哺检查（不自动修改，只给建议）**：

   比较 `user_lean` 和 `final_choice`：
   - 如果一致，且 `satisfaction` ≥ 7 → 该方向对用户效果好，可强化对应 L3 参数的置信度
   - 如果 `satisfaction` ≤ 3 → 说明这个倾向方向对用户来说代价超出预期

   如果检测到有参数反哺价值，告知用户：
   ```
   有一点值得注意——
   这次你偏向了[方向]，但结果满意度不高。
   这可能说明你在[L3某参数]上的实际偏好和档案里的不一样。

   要把这个观察更新到你的替身档案里吗？
   （我只是建议，不会自动改）
   ```

## 模式 3：规律分析

**触发时机**：用户说"分析我的决策规律"、"替身准不准"、"回顾一下"。

### 流程

1. 读取 `decisions.json`，只看有 `follow_up` 数据的条目
2. 如果有效数据 < 2 条，提示：
   ```
   目前只有 {N} 条完整记录，规律还不够清晰。
   多用几次就能看出来了。
   ```
3. 如果有 ≥ 2 条，分析并输出：

```
## 你的决策规律（基于 {N} 条记录）

### 替身准不准
- [变体名] 的立场和你实际选择最一致：{N}/{total} 次
- 你最常偏离的变体是：[变体名]（偏离了 {N} 次）

### 满意度分布
- 平均满意度：{avg}/10
- 最满意的决策：{场景}（{score}/10）
- 最不满意的：{场景}（{score}/10）

### 可能的规律
{基于数据观察到的模式，比如：
 "你有 3/4 次选了更保守的方向，但满意度最高的是那次冒险的选择"}

### 一个值得想的问题
{基于分析，一个用户可能没意识到的模式或矛盾}
```

4. 如果有明显的参数更新建议，在末尾加：
   ```
   基于这些数据，你的[L3某参数]可能需要重新校准。
   要现在更新档案吗？
   ```

## decisions.json 完整结构示例

```json
[
  {
    "id": "a3f2b1c9",
    "date": "2026-03-15T14:30:00",
    "scenario": "要不要放弃技术方向转做 AI 产品",
    "options": ["继续技术路线", "转做 AI 产品经理"],
    "variants_summary": {
      "稳健的你": "3 年积累不应随便放弃，代价太高",
      "果断的你": "AI 窗口期有限，技术背景是优势，早转早受益",
      "长线的你": "五年后产品路线空间更大"
    },
    "user_lean": "可能还是想转，但有点怕",
    "confidence_at_decision": "low",
    "follow_up": {
      "date": "2026-06-20T10:00:00",
      "final_choice": "转了，三个月前入职新公司做产品",
      "outcome": "比想象的顺，但学习曲线陡",
      "satisfaction": 7,
      "lesson": "拖着不决定才是最大的代价，早点做就好了"
    }
  }
]
```
