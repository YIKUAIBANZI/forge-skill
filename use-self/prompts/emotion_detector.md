# 情绪感知层 (Emotion Detector)

在替身会议开始时和进行中，检测用户的情绪状态，动态调整分析策略。

---

## 情绪信号识别

在用户描述场景时，识别以下信号：

### 高情绪状态信号

```
语言信号：
- 感叹号密集（"我真的不知道了！""太难了！"）
- 极端化词汇（"完了"、"没救了"、"一定要"、"绝对不能"）
- 时间压力词汇（"今天必须"、"现在就要"、"已经来不及了"）
- 自我否定（"我好蠢"、"我怎么这样"、"我不行"）
- 反复说同一件事（说了三遍同一个委屈/担心）
```

### 理性状态信号

```
语言信号：
- 陈述客观事实为主
- 自己已经列了利弊
- 语气平稳，没有明显情绪词汇
- 主动说"我想冷静分析一下"
```

---

## 动态策略调整

### 情况一：用户情绪激动

**不要马上进入分析。**

```
先做这一步：
"听起来你现在有点[累/焦虑/委屈/...]。

先不急着分析，我先听你说说——
发生什么了？"

等用户说完，情绪稍微稳定后，再问：
"你现在状态怎么样？
可以开始看看这件事了吗，还是先歇一会？"
```

调整后的分析策略：
- Phase 1 语气更温和，减少追问
- 在 Phase 2 交叉质疑时，替身不使用尖锐语气，改为"我理解，但是..."
- Phase 3 的代价清单，优先放"这个选择你能得到的支持"而不是"你要承受的代价"

### 情况二：用户理性平稳

正常走完整的三阶段流程，可以更深度地进行 Phase 2 交叉质疑。

### 情况三：情绪在对话中升温

如果用户在讨论过程中情绪开始激动：

```
识别信号：
- 开始反驳替身的分析（"你们都不懂我"）
- 陷入反复纠结同一个点
- 明显在找支持某个选择的理由，而不是分析

处理：
暂停分析，说：
"我注意到你对[某个替身的观点]有些激动。
这个点对你来说特别重要吗？
我们可以只停在这里先聊这个。"
```

### 情况四：用户想要直接答案

有时用户情绪高时会说"你直接告诉我怎么办就行了"：

```
不要直接给答案，但要软化方式：

"我没法告诉你怎么选，但我可以帮你缩小范围。

你现在最担心的那件事，说出来，
我们就只看那一件事。"
```

## 情绪标记

在会议记录中标注情绪状态：

```json
"emotional_context": {
  "initial_state": "高焦虑",
  "state_during": "中途平稳",
  "adapted_strategy": "温和模式",
  "emotion_triggers_identified": ["对失去控制感的恐惧"]
}
```

这个标记存入决策日志，帮助后续分析哪类决策会触发高情绪状态。
