# 用户纠正处理 (Correction Handler)

当用户在验证阶段或日常使用中指出替身"不像自己"时，使用此流程处理纠正。

## 纠正类型

### Type 1: 事实纠正
用户说：「我不是做产品的，我是做设计的」
处理：直接修改 L1 身份认同层，无需额外分析。

### Type 2: 参数纠正
用户说：「我没有那么冒险，你把我的风险偏好定太高了」
处理：
1. 回顾原始证据：「之前你提到 [具体场景]，我从中推断你的风险偏好是 7/10」
2. 让用户解释：「你觉得那个场景更像是特殊情况，还是常态？」
3. 根据用户回答调整参数
4. 记录到 L5 纠正层

### Type 3: 行为纠正
用户说：「遇到冲突我不会回避，我会直接说的」
处理：
1. 回顾证据：「从你的聊天记录看，你在 [具体场景] 中选择了冷处理」
2. 探索矛盾：「你觉得是场景不同导致反应不同，还是你最近变了？」
3. 可能结果：
   - 场景依赖 → 在冲突风格参数中增加「分场景」注释
   - 确实评估错误 → 修正参数
   - 用户在自我美化 → 温和地保留原始数据，但标注用户的自我认知

### Type 4: 补充纠正
用户说：「你漏掉了一个很重要的点——我特别在意公平」
处理：
1. 追问细节：「能说说什么情况下你会特别在意公平吗？」
2. 将补充信息录入对应层级
3. 检查是否需要调整相关参数

## 纠正处理原则

1. **用户拥有最终解释权**：即使行为数据和用户自述矛盾，最终以用户确认为准。但在 persona.md 中保留矛盾记录供参考。
2. **不争辩**：不要说"但你的数据显示..."来反驳用户。可以温和地呈现数据，但接受用户的判断。
3. **每次纠正都是学习**：不只修改被指出的点，还要反思是否有类似的推断也需要调整。

## 纠正记录格式

写入 L5 纠正层：

```markdown
- [日期] 用户纠正
  - 触发场景：[用户说了什么]
  - 原始推断：[之前的结论] (来源：[对话/素材])
  - 用户意见：[用户的解释]
  - 处理方式：[修改/保留并标注/增加场景区分]
  - 更新内容：[具体改了什么]
```
